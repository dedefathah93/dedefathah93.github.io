Sekarang kita masuk masalah production yang nyata.

Bayangkan hari ini aplikasi kita mengenal:

```
menunggu
diproses
dikirim
selesai
dibatalkan
```

Lalu backend diperbarui dan menambahkan:

```
dikemas
```

Tetapi user belum memperbarui aplikasi iOS.

Server:

```
{
    "id": 100,
    "status": "dikemas"
}
```

Aplikasi versi lama tidak tahu `"dikemas"`.

Kalau kita hanya menggunakan:

```
enum OrderStatus: String, Codable {
    case waiting = "menunggu"
    case processing = "diproses"
    case shipped = "dikirim"
    case completed = "selesai"
    case cancelled = "dibatalkan"
}
```

maka decoding bisa gagal.

Padahal informasi lain:

```
id = 100
```

sebenarnya valid.

Kita mungkin tidak ingin seluruh Order hilang hanya karena satu status baru.

Salah satu strategi adalah membuat:

```
case unknown
```

Contoh:

```
enum OrderStatus: String {
    case waiting = "menunggu"
    case processing = "diproses"
    case shipped = "dikirim"
    case completed = "selesai"
    case cancelled = "dibatalkan"
    case unknown
}
```

Tetapi sekadar menambahkan `.unknown` belum otomatis menyelesaikan decoding.

Kenapa?

Karena `"dikemas"` tetap tidak sama dengan:

```
"unknown"
```

Jadi kita perlu memberi tahu decoder:

> Kalau String dari server tidak dikenal, gunakan `.unknown`.

Contoh:

```
enum OrderStatus: String, Codable {
    case waiting = "menunggu"
    case processing = "diproses"
    case shipped = "dikirim"
    case completed = "selesai"
    case cancelled = "dibatalkan"
    case unknown

    init(from decoder: Decoder) throws {
        let container = try decoder.singleValueContainer()

        let value = try container.decode(String.self)

        self = OrderStatus(rawValue: value) ?? .unknown
    }
}
```

Ini terlihat lebih kompleks, jadi kita bedah perlahan.

Bagian:

```
init(from decoder: Decoder) throws
```

artinya kita membuat sendiri aturan bagaimana `OrderStatus` di-decode.

Lalu:

```
let container = try decoder.singleValueContainer()
```

secara sederhana:

> Ambil satu nilai yang sedang ingin dibaca oleh decoder.

Karena status kita hanya satu String seperti:

```
"status": "dikemas"
```

Kemudian:

```
let value = try container.decode(String.self)
```

berarti:

> Baca nilai JSON itu sebagai `String`.

Sekarang:

```
value
```

mungkin:

```
"selesai"
```

atau:

```
"dikemas"
```

Kemudian bagian pentingnya:

```
self = OrderStatus(rawValue: value) ?? .unknown
```

Mari hubungkan dengan Hari 2.

Kalau:

```
value = "selesai"
```

maka:

```
OrderStatus(rawValue: value)
```

menghasilkan:

```
.completed
```

Jadi:

```
self = .completed
```

Tetapi kalau:

```
value = "dikemas"
```

maka:

```
OrderStatus(rawValue: value)
```

menghasilkan:

```
nil
```

Kemudian operator:

```
??
```

memberikan fallback:

```
.unknown
```

Jadi:

```
"dikemas"
↓
tidak dikenali
↓
nil
↓
?? .unknown
↓
OrderStatus.unknown
```

Sekarang response tetap bisa di-decode.

---

## Kenapa ini berguna?

Tanpa fallback:

```
status baru dari server
↓
DecodingError
↓
seluruh response mungkin gagal
```

Dengan fallback:

```
status baru dari server
↓
.unknown
↓
Order tetap tersedia
↓
UI bisa menampilkan "Status tidak dikenal"
```

Ini sering disebut sebagai membuat client lebih **forward-compatible** terhadap nilai baru dari backend.

Belum perlu menghafal istilahnya, tetapi pahami idenya.

# Menggunakan `switch`

Sekarang kita bisa:

```
func displayText(
    for status: OrderStatus
) -> String {

    switch status {
    case .waiting:
        return "Menunggu"

    case .processing:
        return "Sedang diproses"

    case .shipped:
        return "Dalam pengiriman"

    case .completed:
        return "Selesai"

    case .cancelled:
        return "Dibatalkan"

    case .unknown:
        return "Status tidak dikenal"
    }
}
```

Kalau:

```
displayText(for: .shipped)
```

hasil:

```
Dalam pengiriman
```

Kalau:

```
displayText(for: .unknown)
```

hasil:

```
Status tidak dikenal
```

Perhatikan pembagian tanggung jawabnya.

Backend menggunakan:

```
"dikirim"
```

Model Swift menggunakan:

```
.shipped
```

UI menggunakan:

```
"Dalam pengiriman"
```

Ketiganya tidak harus menggunakan teks yang sama.

Itu desain yang bagus.

```
Backend representation
"dikirim"

↓

Domain model
.shipped

↓

UI representation
"Dalam pengiriman"
```
