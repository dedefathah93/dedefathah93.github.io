Kita pakai contoh dari aplikasi absensi.

Bayangkan model:

```
struct Attendance {
    let studentName: String
    let status: String
}
```

Kemudian:

```
let attendance = Attendance(
    studentName: "Dede",
    status: "Hadir"
)
```

Kelihatannya baik-baik saja.

Tetapi karena:

```
status: String
```

kita juga bisa menulis:

```
let attendance = Attendance(
    studentName: "Dede",
    status: "Hadri"
)
```

Typo.

Atau:

```
status: "hadir"
```

Atau:

```
status: "HADR"
```

Bahkan:

```
status: "XYZ"
```

Swift tetap menerima semuanya.

Kenapa?

Karena semuanya masih:

```
String
```

Padahal requirement bisnis kita mungkin hanya mengizinkan:

```
Hadir
Sakit
Izin
Alfa
Telat
Dispen
```

Di sinilah kita gunakan:

```
enum
```

---

## Membuat enum

```
enum AttendanceStatus {
    case present
    case sick
    case permission
    case absent
    case late
    case dispensation
}
```

Sekarang model:

```
struct Attendance {
    let studentName: String
    let status: AttendanceStatus
}
```

Membuat data:

```
let attendance = Attendance(
    studentName: "Dede",
    status: .present
)
```

Ini valid.

Tetapi:

```
let attendance = Attendance(
    studentName: "Dede",
    status: .xyz
)
```

tidak bisa.

Compiler akan menolak.

Jadi `enum` membatasi pilihan hanya pada keadaan yang memang valid.

Secara konsep:

```
String
→ hampir apa saja boleh

enum
→ hanya pilihan yang sudah kita definisikan
```

Ini sebenarnya berkaitan langsung dengan salah satu jawaban assessment awal Anda. Waktu itu Anda sudah punya intuisi bahwa status sebaiknya tidak boleh menerima `"xyz"` sembarangan.

Sekarang Anda tahu salah satu cara Swift menyelesaikan masalah tersebut.

---

# Enum bukan sekadar daftar String

Ini penting.

`enum` bukan berarti:

> tempat menyimpan beberapa String.

Enum adalah sebuah **type**.

Contoh:

```
enum AttendanceStatus {
    case present
    case sick
    case permission
}
```

Maka:

```
AttendanceStatus
```

adalah tipe data, sama seperti:

```
String
Int
Bool
Student
```

Kita bisa:

```
let status: AttendanceStatus = .present
```

Jadi sekarang:

```
status
```

bukan sebuah `String`.

Tipenya adalah:

```
AttendanceStatus
```

---

# Membandingkan nilai enum

Misalnya:

```
let status: AttendanceStatus = .sick
```

Kita bisa:

```
if status == .sick {
    print("Siswa sakit")
}
```

Atau:

```
if status == .present {
    print("Siswa hadir")
}
```

# `switch`

Enum sangat sering digunakan bersama:

```
switch
```

Misalnya:

```
enum AttendanceStatus {
    case present
    case sick
    case permission
    case absent
}
```

Kemudian:

```
func statusText(
    status: AttendanceStatus
) -> String {

    switch status {
    case .present:
        return "Hadir"

    case .sick:
        return "Sakit"

    case .permission:
        return "Izin"

    case .absent:
        return "Alfa"
    }
}
```

Perhatikan.

Kita tidak menggunakan banyak:

```
if
else if
else if
```

Kita mengatakan:

> Untuk setiap kemungkinan `AttendanceStatus`, lakukan sesuatu.

---

# Kenapa `switch` dengan enum bagus?

Salah satu kelebihan besar Swift adalah compiler dapat mengetahui semua kemungkinan enum.

Misalnya enum:

```
enum AttendanceStatus {
    case present
    case sick
    case permission
}
```

Tetapi kita menulis:

```
switch status {
case .present:
    print("Hadir")

case .sick:
    print("Sakit")
}
```

Ada yang hilang:

```
.permission
```

Swift akan memperingatkan/error karena `switch` belum menangani semua kemungkinan.

Ini sangat berguna.

Bayangkan beberapa bulan kemudian kita menambahkan:

```
case late
```

Compiler dapat membantu menunjukkan bagian kode yang perlu diperbarui.

Ini jauh lebih aman dibanding String.

# Contoh data modeling yang lebih realistis

Daripada:

```
struct Student {
    let name: String
    let attendanceStatus: String
}
```

lebih baik:

```
enum AttendanceStatus {
    case present
    case sick
    case permission
    case absent
    case late
    case dispensation
}

struct Student {
    let name: String
    let attendanceStatus: AttendanceStatus
}
```

Sekarang data yang invalid jauh lebih sulit masuk.

# Enum dengan raw value

Sekarang misalnya backend Anda menggunakan:

```
{
    "status": "hadir"
}
```

Kita ingin enum Swift tetap punya hubungan dengan String tersebut.

Bisa:

```
enum AttendanceStatus: String {
    case present = "hadir"
    case sick = "sakit"
    case permission = "izin"
    case absent = "alfa"
}
```

Sekarang:

```
AttendanceStatus.present.rawValue
```

hasil:

```
"hadir"
```

Dan:

```
AttendanceStatus.sick.rawValue
```

hasil:

```
"sakit"
```

Perhatikan:

```
present
```

adalah nama case di Swift.

Sedangkan:

```
"hadir"
```

adalah raw value String-nya.

# Membuat enum dari String

Misalnya server mengirim:

```
let serverStatus = "sakit"
```

Kita dapat mencoba:

```
let status = AttendanceStatus(
    rawValue: serverStatus
)
```

Apa tipe `status`?

Bukan:

```
AttendanceStatus
```

melainkan:

```
AttendanceStatus?
```

Kenapa Optional?

Karena String dari server mungkin tidak cocok.

Misalnya:

```
AttendanceStatus(rawValue: "sakit")
```

menghasilkan:

```
.sick
```

Tetapi:

```
AttendanceStatus(rawValue: "XYZ")
```

menghasilkan:

```
nil
```

Karena tidak ada case dengan raw value `"XYZ"`.

Jadi lagi-lagi materi Optional kita muncul.

# Enum + Codable

Sekarang kita gabungkan dengan Hari 2.

```
enum AttendanceStatus: String, Codable {
    case present = "hadir"
    case sick = "sakit"
    case permission = "izin"
    case absent = "alfa"
}
```

Model:

```
struct Attendance: Codable {
    let studentName: String
    let status: AttendanceStatus
}
```

JSON:

```
{
    "studentName": "Dede",
    "status": "hadir"
}
```

`JSONDecoder` dapat mengubah:

```
"hadir"
```

menjadi:

```
AttendanceStatus.present
```

Ini sudah mendekati code production sungguhan.

Pipeline-nya:

```
Server
↓
"hadir"
↓
JSONDecoder
↓
AttendanceStatus.present
↓
logic aplikasi
↓
SwiftUI
```
