
# Memahami Optional dalam Swift

Optional digunakan ketika sebuah nilai
mungkin tersedia atau bernilai nil.

## Contoh

```swift
var nama: String? = nil
nama = "Budi"
```

Anda tadi belum memahami:
```
String?
```

Ini akan menjadi materi Hari 2, tetapi saya berikan mental model sekarang.
```
String
```

berarti:
> harus ada String.

Sedangkan:
```
String?
```

berarti:
> bisa ada String, bisa juga tidak ada nilai.

Contoh:
```
let name: String = "Dede"
```
`name` harus mempunyai nilai.

Tetapi:
```
let phoneNumber: String? = nil
```
boleh kosong.

`nil` berarti tidak ada nilai.

Jadi:
```
String?
```
bukan berarti “mungkin String jenis lain”.

Artinya:
```
String
ATAU
nil
```

Contoh dunia nyata:
```
struct User {
    let name: String
    let phoneNumber: String?
}
```
Nama wajib.
Nomor telepon tidak wajib.

Maka ini valid:
```
User(
    name: "Dede",
    phoneNumber: nil
)
```

Sedangkan tanda:
```
!
```

pada:
```
user.phoneNumber!
```

kurang lebih berarti:
> “Saya yakin isinya ada. Paksa Swift mengambilnya.”

Masalahnya tadi:
```
phoneNumber: nil
```

lalu:
```
user.phoneNumber!
```

Anda mengatakan:
> “Saya yakin ada.”

Padahal tidak ada.
Hasilnya program crash.

Ini salah satu error Swift yang nanti sangat sering Anda temui:
```
Unexpectedly found nil while unwrapping an Optional value
```

Kita bahas penuh besok.

---

Mari mulai dari masalah nyata.

Misalnya kita punya pengguna:
```
struct User {
    let name: String
    let phoneNumber: String
}
```

Kemudian:
```
let user = User(
    name: "Dede",
    phoneNumber: "08123456789"
)
```

Tidak ada masalah.

Tetapi bagaimana kalau pengguna tidak mempunyai nomor telepon?

Kita tidak bisa menulis:
```
let user = User(
    name: "Dede",
    phoneNumber: nil
)
```

karena kita mengatakan:
```
phoneNumber: String
```

Artinya:
> phoneNumber harus berupa String.

Swift tidak mengizinkan `nil`.

Di sinilah Optional digunakan.
```
struct User {
    let name: String
    let phoneNumber: String?
}
```

Perhatikan:
```
String?
```

Artinya:
```
String
atau
tidak ada nilai
```

Jadi sekarang kedua data ini valid:
```
let userA = User(
    name: "Dede",
    phoneNumber: "08123456789"
)
```

dan:
```
let userB = User(
    name: "Ahmad",
    phoneNumber: nil
)
```

`nil` berarti:
> tidak ada nilai.

Bukan string kosong.

Ini berbeda:
```
phoneNumber: ""
```

dengan:
```
phoneNumber: nil
```

Yang pertama masih mempunyai String, hanya saja String-nya kosong.

Yang kedua benar-benar tidak mempunyai nilai.

### Kenapa Swift repot-repot membuat Optional?
Karena Swift ingin memaksa programmer menangani kemungkinan data tidak tersedia.

Misalnya backend memberi:
```
{
  "name": "Dede",
  "phone": null
}
```

Kalau model Anda:
```
let phone: String
```

ada masalah.

Tetapi:
```
let phone: String?
```

mengatakan:
> Saya sadar bahwa nomor telepon mungkin tidak tersedia.

Optional sangat sering muncul pada aplikasi nyata.

Contohnya:
```
var currentUser: User?
var profileImageURL: String?
var errorMessage: String?
var selectedStudent: Student?
var token: String?
```

Karena semua hal tersebut pada suatu waktu mungkin belum memiliki nilai.

## Masalah berikutnya

Misalkan:
```
let phoneNumber: String? = "08123456789"
```

Kita tahu ada nomor.

Tetapi Swift melihat tipenya:
```
String?
```

bukan:
```
String
```

Maka kita tidak boleh sembarangan memperlakukannya sebagai String biasa.

Karena kemungkinan lainnya adalah:
```
let phoneNumber: String? = nil
```

Jadi Optional seperti kotak:
```
phoneNumber

┌────────────────────┐
│ "08123456789"      │
└────────────────────┘
```

atau:
```
phoneNumber

┌────────────────────┐
│ nil                │
└────────────────────┘
```

Sebelum menggunakan isi kotaknya, kita perlu memastikan ada isinya.

# Force unwrap: `!`

Sekarang kita kembali ke soal assessment Anda:
```
struct User {
    let name: String
    let phoneNumber: String?
}

let user = User(
    name: "Dede",
    phoneNumber: nil
)

print(user.phoneNumber!)
```

Tanda:
```
!
```
disebut force unwrap.

Secara konsep Anda sedang mengatakan kepada Swift:
> Saya tahu ini Optional, tetapi saya jamin ada nilainya. Berikan isinya kepada saya.

Contoh:
```
let phone: String? = "08123"

print(phone!)
```

hasil:
```
08123
```

Tetapi:
```
let phone: String? = nil

print(phone!)
```
crash.

Karena Anda menjanjikan:
> ada nilai.

Padahal:
```
nil
```

Itulah sumber error terkenal:
```
Fatal error:
Unexpectedly found nil while unwrapping an Optional value
```

Jadi salah satu aturan kita:
```
Jangan menggunakan ! hanya karena ingin compiler berhenti protes.
```
Ini kebiasaan buruk yang sering muncul pada kode hasil copy paste.

# Cara lebih aman: `if let`

Misalnya:
```
let phoneNumber: String? = "08123456789"
```

Kita bisa melakukan:
```
if let phone = phoneNumber {
    print(phone)
}
```

Baca seperti bahasa manusia:
> Jika `phoneNumber` mempunyai nilai, ambil nilainya dan sebut sebagai `phone`.

Alurnya:
```
phoneNumber
    ↓
ada nilai?
    ↓
 YA
    ↓
phone = nilai tersebut
    ↓
print(phone)
```

Kalau:
```
let phoneNumber: String? = nil
```

blok ini:
```
if let phone = phoneNumber {
    print(phone)
}
```

tidak dijalankan.

Kita juga bisa:
```
if let phone = phoneNumber {
    print(phone)
} else {
    print("Nomor telepon belum tersedia")
}
```

Ini jauh lebih aman.

---

# Contoh aplikasi nyata

Misalkan kita mempunyai:
```
struct Student {
    let name: String
    let note: String?
}
```

Siswa pertama:

```
let student = Student(
    name: "Ahmad",
    note: "Datang terlambat"
)
```

Kita lakukan:
```
if let note = student.note {
    print(note)
} else {
    print("Tidak ada catatan")
}
```

Hasil:
```
Datang terlambat
```

Tetapi:
```
let student = Student(
    name: "Ahmad",
    note: nil
)
```

hasilnya:
```
Tidak ada catatan
```

# Cara lain: `??`

Ada operator yang akan sangat sering Anda lihat:
```
??
```

Namanya nil-coalescing operator.

Contoh:
```
let phone: String? = nil

let displayedPhone = phone ?? "Tidak tersedia"
```

Artinya:
> Gunakan `phone` kalau ada. Kalau nil, gunakan `"Tidak tersedia"`.

Hasil:
```
displayedPhone = "Tidak tersedia"
```

Kalau:
```
let phone: String? = "08123"
```

maka:
```
displayedPhone = "08123"
```

Ini sangat sering digunakan di UI.

Contoh:
```
Text(user.phoneNumber ?? "Belum ada nomor")
```

# Ada satu lagi yang sangat penting: `guard let`

Misalnya kita membuat function:
```
func callUser(phoneNumber: String?) {

    guard let phone = phoneNumber else {
        print("Nomor telepon tidak tersedia")
        return
    }

    print("Menghubungi \(phone)")
}
```

Baca:
> Pastikan `phoneNumber` memiliki nilai. Kalau tidak ada, hentikan function.

Kalau ada:
```
phoneNumber
↓
ada
↓
lanjut function
```

Kalau nil:
```
phoneNumber
↓
nil
↓
else
↓
return
↓
function berhenti
```

Nanti Anda akan sering melihat bentuk seperti:
```
guard let user = currentUser else {
    return
}
```

atau:
```
guard let token = authToken else {
    throw AuthError.notLoggedIn
}
```

---

## `if let` versus `guard let`

Untuk sekarang gunakan mental model sederhana:
```
if let
→ lakukan sesuatu JIKA datanya ada
```

Sedangkan:
```
guard let
→ data ini WAJIB ada agar function bisa dilanjutkan
```

Contoh `if let`:
```
if let profileImage = user.profileImage {
    tampilkanGambar(profileImage)
}
```

Gambar profil opsional. Kalau tidak ada, tidak masalah.

Contoh `guard let`:
```
guard let token = authToken else {
    return
}
```

Untuk request authenticated, token diperlukan. Kalau tidak ada, percuma melanjutkan.

Ini perbedaan yang nanti sangat penting.

Tadi kita punya:
```
let username = currentUser!.name
```

Kalau crash:
```

```

yang kita curigai adalah:
```
currentUser == nil
```

Bukan:
```
currentUser.name kosong
```

Perhatikan:
```
currentUser!
      ↑
yang di-force unwrap
```

Alternatif:
```
guard let user = currentUser else {
    return
}

let username = user.name
```

Sekarang:
```
currentUser ada?
       ↓
      YA
       ↓
user
       ↓
user.name
```

Kalau nil:
```
currentUser
↓
nil
↓
return
```

Tidak crash.

Tetapi sebagai developer kita tetap harus bertanya:
> Kenapa `currentUser` nil?

Karena hanya mencegah crash belum tentu menyelesaikan root cause.

Misalnya seharusnya halaman tersebut tidak boleh terbuka sebelum login. Maka bug sebenarnya mungkin berada pada navigation/authentication, bukan pada Optional.

Ini bagian debugging yang nanti akan kita latih.

## Optional Chaining

Misalnya:
```
struct Profile {
    let city: String
}

struct User {
    let name: String
    let profile: Profile?
}

let user = User(
    name: "Dede",
    profile: Profile(city: "Bandung")
)
```

Kita ingin mengambil:
```
user.profile.city
```

Masalahnya `profile` bertipe:
```
Profile?
```
Jadi Swift tidak yakin `profile` benar-benar ada.

Kita bisa melakukan:
```
if let profile = user.profile {
    print(profile.city)
}
```

Tetapi Swift menyediakan cara yang lebih ringkas:
```
print(user.profile?.city)
```

Perhatikan:
```
?.
```
Ini disebut optional chaining.

Artinya kira-kira:
> Kalau `profile` ada, lanjut ambil `city`. Kalau `profile` nil, hasil akhirnya nil.

Misalnya:
```
let user = User(
    name: "Dede",
    profile: nil
)
```

Kemudian:
```
let city = user.profile?.city
```

hasilnya:
```
city = nil
```
Program tidak crash.

Bandingkan dengan:
```
let city = user.profile!.city
```
Kalau `profile == nil`, crash.

Jadi:
```
?.
→ kalau ada, lanjut
→ kalau nil, berhenti dengan aman

!.
→ saya paksa karena yakin ada
→ kalau ternyata nil, crash
```

Sekarang kita gabungkan dengan `??`.
```
let city = user.profile?.city ?? "Kota belum tersedia"
```

Artinya:
```
profile ada?
↓
YA
↓
ambil city

TIDAK
↓
"Kota belum tersedia"
```

Ini akan sangat sering Anda lihat di SwiftUI:
```
Text(user.profile?.city ?? "Belum ada kota")
```

Sekarang sedikit lebih nyata.
Bayangkan model dari API:
```
struct Teacher {
    let name: String
    let contact: Contact?
}

struct Contact {
    let phone: String?
}
```

Data bisa seperti:
```
Teacher
└── contact
    └── phone
```

atau:
```
Teacher
└── contact = nil
```

atau bahkan:
```
Teacher
└── contact
    └── phone = nil
```

Kita bisa menulis:
```
let phone = teacher.contact?.phone
```

Swift mengecek rantainya.
```
teacher
↓
contact ada?
↓
phone ada?
```

Karena itu namanya chaining.

Sekarang kita masuk sedikit ke debugging.
Perhatikan kode:
```
struct User {
    let name: String
    let token: String?
}

func loadDashboard(user: User?) {
    print("Mulai load dashboard")

    let token = user!.token!

    print("Menggunakan token \(token)")
}
```

Kemudian:
```
let currentUser: User? = User(
    name: "Dede",
    token: nil
)

loadDashboard(user: currentUser)
```

Di sini ada dua:
```
!
```

Pertama:
```
user!
```
artinya kita memaksa bahwa `user` ada.

Kedua:
```
token!
```
artinya kita memaksa bahwa token ada.

Dalam contoh ini:
```
user
→ ada

token
→ nil
```

Jadi crash terjadi pada:
```
token!
```

Bukan pada:
```
user!
```

Ini penting dalam debugging. Kita harus tahu Optional mana yang nil.

Cara lebih aman:
```
func loadDashboard(user: User?) {
    guard let user = user else {
        print("User belum login")
        return
    }

    guard let token = user.token else {
        print("Token tidak tersedia")
        return
    }

    print("Menggunakan token \(token)")
}
```

Sekarang alurnya jelas:
```
user ada?
↓
tidak
→ berhenti

ya
↓
token ada?
↓
tidak
→ berhenti

ya
↓
load dashboard
```

Ini salah satu pola Swift yang akan sering sekali Anda temui.

## Hal yang perlu saya ingat

- String dan String? adalah tipe yang berbeda.
- Optional perlu ditangani sebelum nilainya
  digunakan pada operasi yang membutuhkan
  nilai non-optional.
- Salah satu caranya menggunakan if let.
