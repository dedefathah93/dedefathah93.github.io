Gunakan:

```
enum PaymentStatus: String, Codable {
    case pending = "pending"
    case paid = "paid"
    case failed = "failed"
    case unknown

    init(from decoder: Decoder) throws {
        let container = try decoder.singleValueContainer()
        let value = try container.decode(String.self)

        self = PaymentStatus(rawValue: value) ?? .unknown
    }
}
```

Jawab:

1. Apa hasil jika backend mengirim:

```
"paid"
```

2. Apa hasil jika backend mengirim:

```
"failed"
```

3. Apa hasil jika backend mengirim:

```
"refunded"
```

4. Kenapa `"refunded"` tidak menyebabkan `nil` menjadi nilai akhir?
    
5. Apa fungsi:
    

```
?? .unknown
```

6. Apa tipe:

```
PaymentStatus(rawValue: "paid")
```

7. Apa tipe:

```
PaymentStatus(rawValue: "refunded")
```

8. Nilai nomor 7 apa?
    
9. Apa perbedaan antara:
    

```
PaymentStatus(rawValue: "refunded")
```

dan decoding `"refunded"` menggunakan custom decoder di atas?

10. Menurut Anda, kenapa `.unknown` bisa lebih aman untuk aplikasi production dibanding membiarkan seluruh response gagal hanya karena backend menambahkan satu status baru?

Jawaban:
1. .paid
2. .failed
3. .unknown
4. dikarenakan operator ?? memberikan fallback .unknown
5. jika nilai dari backend tidak ada dalam case maka operator akan memasukkannya kedalam kategori .unknown
6. case paid
7. case unknown
8. nill
9. tidak tahu
10. karena supaya aplikasi tetap bisa berjalan

Tanggapan
Nomor 1 sampai 5 sudah benar. Nomor 6, 7, 8, dan 9 perlu diperbaiki karena di sini ada perbedaan penting antara **tipe** dan **nilai**.

Untuk nomor 6:

```
PaymentStatus(rawValue: "paid")
```

tipenya adalah:

```
PaymentStatus?
```

Nilainya:

```
.paid
```

Jadi bedakan:

```
Tipe   → PaymentStatus?
Nilai  → .paid
```

Nomor 7 juga tipenya tetap:

```
PaymentStatus?
```

meskipun raw value-nya tidak dikenal.

Nomor 8, nilainya:

```
nil
```

bukan `.unknown`.

Kenapa?

Karena ini hanya memakai initializer bawaan:

```
PaymentStatus(rawValue: "refunded")
```

Swift mencoba mencocokkan:

```
"refunded"
↓
pending? tidak
paid? tidak
failed? tidak
unknown? rawValue-nya "unknown", jadi tidak
↓
nil
```

Ini berbeda dengan custom decoder kita.

Untuk nomor 9, sekarang kita bandingkan langsung.

Kalau Anda menulis:

```
PaymentStatus(rawValue: "refunded")
```

hasilnya:

```
nil
```

karena initializer bawaan tidak punya fallback.

Tetapi ketika `JSONDecoder` memakai custom initializer ini:

```
self = PaymentStatus(rawValue: value) ?? .unknown
```

alur menjadi:

```
"refunded"
↓
PaymentStatus(rawValue:)
↓
nil
↓
?? .unknown
↓
.unknown
```

Jadi perbedaannya:

```
rawValue initializer langsung
→ unknown String menghasilkan nil

custom Codable decoder
→ unknown String menghasilkan .unknown
```

Nomor 10 benar. Tujuannya agar aplikasi tidak langsung gagal hanya karena backend menambahkan nilai status yang versi aplikasi lama belum kenal.

Ada satu nuance penting lagi.

Custom decoder kita masih bisa `throw`.

Misalnya backend mengirim:

```
123
```

untuk status.

Padahal kode ini:

```
let value = try container.decode(String.self)
```

meminta `String`.

Maka decoding tetap bisa gagal karena tipe datanya salah.

Jadi `.unknown` menangani:

```
String valid
tetapi nilainya tidak dikenal
```

bukan semua kemungkinan error.
