Kita mulai dari enum sederhana:

```
enum PaymentStatus {
    case pending
    case paid
    case failed
}
```

Lalu:

```
func message(
    for status: PaymentStatus
) -> String {

    switch status {
    case .pending:
        return "Menunggu pembayaran"

    case .paid:
        return "Pembayaran berhasil"

    case .failed:
        return "Pembayaran gagal"
    }
}
```

Kalau:

```
message(for: .paid)
```

hasil:

```
Pembayaran berhasil
```

`switch` memeriksa nilai enum lalu menjalankan case yang cocok.

Secara konsep:

```
status
↓
switch
├── pending
├── paid
└── failed
```

Satu kelebihan `switch` dengan enum adalah Swift meminta semua kemungkinan ditangani.

Kalau enum:

```
enum PaymentStatus {
    case pending
    case paid
    case failed
    case refunded
}
```

tetapi switch masih:

```
switch status {
case .pending:
    ...
case .paid:
    ...
case .failed:
    ...
}
```

Swift akan protes karena:

```
.refunded
```

belum ditangani.

Ini berguna ketika aplikasi berkembang.

---

Sekarang kita masuk fitur enum Swift yang lebih menarik: **associated value**.

Bayangkan kita membuat status loading.

Versi pertama:

```
enum LoadState {
    case idle
    case loading
    case success
    case failure
}
```

Ini sudah berguna.

Tetapi saat `success`, kita mungkin ingin membawa data.

Saat `failure`, kita ingin membawa pesan error.

Swift memungkinkan:

```
enum LoadState {
    case idle
    case loading
    case success(String)
    case failure(String)
}
```

Sekarang:

```
let state: LoadState = .success("Data berhasil dimuat")
```

Case `.success` membawa data tambahan:

```
"Data berhasil dimuat"
```

Dan:

```
let state: LoadState = .failure("Tidak ada koneksi")
```

membawa pesan error.

String tersebut disebut:

```
associated value
```

Artinya nilai yang menempel pada sebuah case enum.

Sekarang kita ambil menggunakan `switch`:

```
func displayMessage(
    state: LoadState
) -> String {

    switch state {
    case .idle:
        return "Belum mulai"

    case .loading:
        return "Memuat..."

    case .success(let message):
        return message

    case .failure(let error):
        return error
    }
}
```

Perhatikan:

```
case .success(let message):
```

Artinya:

> Kalau state adalah `.success`, ambil String yang ada di dalamnya dan simpan sementara ke variable `message`.

Kalau:

```
let state = LoadState.success(
    "Data berhasil dimuat"
)
```

maka saat switch:

```
message = "Data berhasil dimuat"
```

Begitu juga:

```
case .failure(let error):
```

mengambil associated value ke variable:

```
error
```

---

Contoh yang lebih realistis untuk aplikasi:

```
struct Student {
    let name: String
}
```

Kemudian:

```
enum StudentLoadState {
    case idle
    case loading
    case success([Student])
    case failure(String)
}
```

Perhatikan:

```
case success([Student])
```

berarti kalau berhasil, state membawa:

```
[Student]
```

bukan sekadar String.

Misalnya:

```
let state = StudentLoadState.success([
    Student(name: "Ahmad"),
    Student(name: "Rina")
])
```

Kemudian:

```
switch state {
case .idle:
    print("Belum dimulai")

case .loading:
    print("Loading")

case .success(let students):
    print(students.count)

case .failure(let message):
    print(message)
}
```

Pada case success:

```
students
```

bertipe:

```
[Student]
```

Jadi enum sekarang tidak hanya mengatakan:

```
success
```

tetapi:

```
success + datanya
```

Begitu pula:

```
failure + pesan error
```

Ini sangat berguna untuk state management nanti di SwiftUI.

Daripada punya banyak variable:

```
var isLoading: Bool
var students: [Student]
var errorMessage: String?
```

yang bisa masuk kondisi aneh seperti:

```
isLoading = true
students ada
errorMessage juga ada
```

kita bisa merepresentasikan kondisi sebagai satu enum:

```
enum StudentLoadState {
    case idle
    case loading
    case success([Student])
    case failure(String)
}
```

Sehingga state hanya bisa menjadi salah satu:

```
idle
atau
loading
atau
success
atau
failure
```

Ini jauh lebih sulit menghasilkan kombinasi state yang tidak masuk akal.
