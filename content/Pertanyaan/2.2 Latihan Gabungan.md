Tanggapan
Jawaban Anda sudah benar hampir seluruhnya. Yang masih perlu diperkuat hanya nomor 10 karena itu inti dari data modeling.

Nomor 1 sampai 9, 11, dan 12 sudah tepat.

Untuk nomor 4 dan 12, jawaban Anda benar secara isi. Bentuk hasil konkretnya:

```
[
    "ahmad@mail.com",
    "dede@mail.com"
]
```

dengan tipe:

```
[String]
```

Nomor 10, Anda menjawab:

> State lebih terstruktur  
> Konsep enum

Arah ini benar, tetapi kita perlu membuatnya lebih tajam.

Kalau memakai tiga variable terpisah:

```
var isLoading: Bool
var students: [Student]
var errorMessage: String?
```

kita bisa tanpa sengaja membuat kondisi yang tidak masuk akal:

```
isLoading = true

students = [
    Student(...)
]

errorMessage = "Server error"
```

Sekarang aplikasi seperti mengatakan tiga hal sekaligus:

```
sedang loading
+
sudah punya data
+
sedang error
```

Padahal secara logika biasanya state utama harus salah satu.

Dengan:

```
enum StudentLoadState {
    case idle
    case loading
    case success([Student])
    case failure(String)
}
```

state hanya bisa menjadi:

```
idle

atau

loading

atau

success + data

atau

failure + error
```

Tidak bisa semuanya aktif sekaligus.

Ini konsep engineering yang sangat penting:

> model data sebaiknya membuat kondisi yang salah menjadi sulit, atau bahkan mustahil, untuk direpresentasikan.

Kalimat itu nanti akan sering kita pakai.
