Sekarang saya ingin menutup Hari 2 dengan satu debugging challenge. Ini penting karena kita tidak mau hanya memahami Optional saat contoh sudah rapi.

Perhatikan kode:

```
struct Profile: Codable {
    let name: String
    let email: String?
    let age: Int
}

let json = """
{
    "name": "Dede",
    "email": null,
    "age": "35"
}
""".data(using: .utf8)!

do {
    let profile = try JSONDecoder().decode(
        Profile.self,
        from: json
    )

    print(profile.name)
} catch {
    print("Gagal decode")
}
```

Jawab lima hal:

1. Apakah `name` bermasalah?
2. Apakah `email` bermasalah? Jelaskan kenapa `null` aman atau tidak.
3. Property mana yang menyebabkan decoding gagal?
4. Kenapa ia gagal?
5. Apa perubahan paling sederhana pada model Swift agar JSON tersebut bisa di-decode, dengan asumsi backend memang selalu mengirim `age` sebagai `"35"` berbentuk String?

Jawaban:
1. tidak bermasalah
2. email tidak bermasalah karena dia menggunakan String? .
3. property pada Profile Age
4. karena dari JSON dia memberikan string bukan int
5. merubah let age: Int menjadi let age: String?
   
Tanggapan:
Empat jawaban pertama benar. Nomor 5 hampir benar, tetapi ada satu konsep penting yang perlu diluruskan.

Kalau backend memang selalu mengirim:

```
"age": "35"
```

maka perubahan paling sederhana adalah:

```
let age: String
```

bukan:

```
let age: String?
```

Karena masalahnya adalah tipe datanya, bukan kemungkinan `nil`.

Bedakan dua pertanyaan ini:

```
Apakah datanya String atau Int?
→ type

Apakah datanya bisa tidak ada?
→ Optional
```

Jadi:

```
let age: String
```

berarti selalu ada dan berbentuk String.

```
let age: String?
```

berarti bisa String atau `nil`.

Kalau backend selalu mengirim String dan tidak pernah `null`, maka `String` lebih tepat.
